# The Debrief — a briefing on demand, compared against 07:00: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Debrief now" button at the foot of the Briefing panel re-checks everything the morning push checks (run history, the three sites, ShikksTracker's sender and attention feed, today's calendar, to-dos and queue), compares the result against today's 07:00 Briefing (Sorted · Still needs you · New, or a flat "Right now" list when there is no morning Briefing), saves it as the one latest Debrief, and the greeting line shows it until the next morning's 07:00 Briefing takes over. Site only: no push, no expiry sweep, no outward action.

**Architecture:** Every decision is in pure modules pinned by tests: `debriefCompare.ts` (the matching rules, the Sorted/can't-say/standalone words), `debrief.ts` (fresh problems, the stored record, the title), `debriefView.ts` (the panel's view model and the response parser), `briefingView.ts` (the greeting line's recency rule), and `voice.ts` (the time-of-day heading). The impure edges are thin: `debriefRead.ts` (every read bounded and caught on its own, the site floor shared with "Check now"), `debriefDoor.ts` (the press: cache, `runJob`, save last) behind a three-line `POST /api/briefing/debrief`, `lastDebrief.ts` + `models/LastDebrief.ts` (R55's singleton), and the existing `BriefingSlot.tsx` / `Briefing.tsx` island.

**Tech Stack:** Next.js 16 App Router (RSC + one client island) · React 19 · TypeScript `strict` · Mongoose 9 · Vitest 4. **No new dependency in package.json. No new `@media` rule. No index change** (a new collection with only `_id`; the `AgentRun` enum grows, which Mongoose does not treat as an index change).

**Spec:** `docs/superpowers/specs/2026-10-10-debrief-design.md` — approved by Riku 2026-10-11, **including every §10 wording as written**. Where this plan refines the spec, the refinement is listed in "Deviations from the spec" below and is binding. Decision: **S22** (recorded by Task D0 in `ARCHITECTURE.md` §7). Read the sibling S21 spec and Plan B (`docs/superpowers/plans/2026-10-09-briefing-b-on-the-site.md`) first: this plan extends their code.

## Deviations from the spec (binding)

1. **Sites and agents match by family and subject, not by exact key (spec §3.5 step 4 said `(key, subject)`).** A site yields at most one `site-*` problem and an agent at most one `agent-*` anomaly (`classifyAgentRun` returns one verdict), so a stored `site-status` for Meowchi matches a fresh `site-timeout` for Meowchi. Under exact-key matching that site would read **"Meowchi's site is back up."** plus a New row while it is still down — a false "sorted", which the spec's own rule ("never claim sorted for anything not re-checked") forbids. Every other key still matches exactly.
2. **A baseline saved before `subject` existed falls back to the sentence's bold lead, not to sentence equality (spec §5.1).** `agent-stale`'s sentence carries hours that grow between 07:00 and the press ("hasn't run in 31 hours" → "37 hours"), so `(key, sentence)` equality would always call a still-stale agent sorted. The catalogue always bolds the subject first (`Meowchi's site`, `The chaser`), so the lead identifies the same thing. Two consequences: a subject-less `job-failed` can't be placed (no fresh `job-failed` exists to compare against, and its source is unknown), so it stays in Still needs you verbatim, like the not-re-checkable keys; a subject-less `calendar-partial` matches any fresh `calendar-partial`. Only the deploy day's 07:00 record can be subject-less. The sorted-sentence fallbacks for an unreadable lead (`That site` / `That job` / `That check`) can only fire on a corrupt record.
3. **`HealthSnapshot` stores each site's `failure` and `status` (optional, bounded, no index).** The spec reuses a snapshot inside the 60-second floor, but the snapshot dropped how a site failed, so every reused down site would re-explain as "can't be reached at all" even when it is answering with error 503. The Freelance page's strip reads only `name/up/detail` and is unaffected.
4. **The per-symptom can't-say line is a separate `note` on the Still-needs-you row, not part of its sentence.** The spec calls it a suffix (§10 item 4) and says the symptom moves "unchanged"; a 200-character symptom sentence plus an 85-character note can't fit `BRIEFING_BOUNDS.symptomSentence`, and clipping would risk bold ranges. So `StoredDebriefSymptom` = `StoredSymptom` + `note: string | null` (≤ 120). The spec never quotes the ShikksTracker wording it calls Riku's literal example; this plan uses `I couldn't reach ShikksTracker just now, so I can't say whether that's sorted.`, the approved sites/watchdog pattern with the approved standalone line's subject. **Flagged for Riku's nod.**
5. **The title's count and the line's tone include the standalone couldn't-check lines and the no-baseline `now` list** (spec §2.2 counted `stillNeedsYou + new` only). Without this, a press where ShikksTracker didn't answer and nothing was wrong at 07:00 would read **"Debrief at 13:04: all clear."** over a source it couldn't check — a claim the voice rules forbid (S21 §2: never claim more than it knows).
6. **The New-row time stamp is added only to `agent-failed` and `agent-degraded`, and only when that run started today** (spec §4.2/§10 item 5 said every `agent-*` row). `agent-never-ran` has no run to stamp, and `agent-stale`'s sentence is about an absence: "The chaser hasn't run in 9 hours at 11:00." would be false. The stamp marks the run the sentence is about.
7. **The `unsaved` greeting-line state now opens the last stored Briefing** (`opens: "digest"` when one exists; it was `null`). Spec §3.6 says the existing branches are unchanged, but D4 (Riku's settled decision) says the panel, and so the Debrief button, is reachable "whenever any briefing is stored, even an older one — only never/fail states can't reach it". `unsaved` was the one other state that blocked it. It now behaves like `failed`, `monitoring-off` and `skipped`, which already open the older Briefing.
8. **The baseline is today's digest only if it carries a structured Briefing.** A today's digest saved with `briefing: null` (a pre-S21 record, or a Briefing that couldn't be built) has no symptoms to compare, and a baseline read that fails can't be compared against either: both mean "no baseline", so the Debrief shows the flat "Right now" list (D5's no-comparison case) rather than a comparison against nothing.
9. **The door reads the baseline first, then the fresh checks:** `readDebriefChecks(now, baselineSentAt)`. "What you've done" (§4.4) needs `baseline.sentAt` to read since-then, so the spec's order (checks, then baseline) can't supply it. The baseline read is one bounded Mongo read (≤ 5 s).
10. **`groupProblems()` is not run.** Spec §3.4 says it "still runs over the fresh list", but the stored shape (§5.1) is per-symptom rows with no story field, so nothing would consume its output.
11. **The door's logic lives in `src/lib/debriefDoor.ts` (`pressDebrief(now)`), and the route only checks the session and serialises.** CLAUDE.md: route handlers stay thin so the logic layer holds the behaviour. This lets `debriefDoor.test.ts` pin the cache, the run row, the save failure and the typed 500s (spec §7.2 items 7, 8, 11, 12) without a server — the first door with tests at this level.
12. **Identical Sorted sentences are stored once.** `engine-stale` and `stranded-approved` clearing together would otherwise read "ShikksTracker's sender is moving again." twice.
13. **Two short strings the spec does not give, written by this plan (provisional, for Riku's nod):** the no-baseline empty line `Nothing needs you right now.`; the panel's kicker over a Debrief, `Debrief · 13:04`. The wait text is Riku's own approved wording, `Checking your sites and ShikksTracker…` (lead ruling 2026-10-11), not a plan string.
14. **Where the controls appear.** "Debrief now" is in the panel only, never in the once-a-day full-screen greeting (D4). "This morning's briefing →" appears only when today's Briefing exists (on a morning without one, the words would be false). "← Debrief" appears in the morning view only when a today's Debrief is available.
15. **A pre-existing bug fixed in passing: `npm run migrate:indexes` fails today.** `src/models/LastDigest.ts` imports `@/lib/briefingTypes`, and `scripts/sync-indexes.mts` loads models under `node --experimental-strip-types`, which resolves no `@/` alias (checked 2026-10-11: `ERR_MODULE_NOT_FOUND: Cannot find package '@/lib'`). D3 switches it to the relative `../lib/briefingTypes.ts` import that `ApprovalItem.ts` already uses, gives `LastDebrief.ts` the same, and registers `LastDebrief` in the sync script. Running the script is not needed for this plan (no index change).
16. **`compareToBaseline`'s snapshot argument is `{ checkedAt: Date | null; … }`** (spec: `Date`). No snapshot ever saved is `null`, which reads as "not saved since this morning" → Still needs you.
17. **Small defaults where a read failed.** Settings unreadable → the calendar reads as unavailable (`read-failed`), the attention read uses the default `chaserNDays`, and the off line is left out (it can't be known). Pending count unreadable → the freelance line leaves drafts out. A client-side timeout or failure still calls `router.refresh()`, so a Debrief that finished on the server after the browser stopped waiting still reaches the line (D7).
18. **Two calendar reads per press** (`readDigestToday` for Rest of today, `readSinceThen` for What you've done). Reusing both readers unchanged is worth one extra bounded Google read.
19. **"All clear, same as this morning." is decided in the view (`debriefView.ts`), not in `debrief.ts`** (spec §7.1 lists it under `debrief.ts`'s tests). It is a rendering of an all-empty comparison, so it lives and is tested beside the other headings.
20. **Noted, not changed:** `APPROVAL_SOURCES` (`ApprovalItem.ts`) is `[...AGENTS, "manual"]`, so it gains `"debrief"` too — harmless, exactly as it already lists `watchdog` and `site-health`, which never propose items either. No index or read keys on it.
21. **Four false-Sorted/double-report cases found in the D-II feature review, all fixed in `debriefCompare.ts`.** (a) `site-health` and `outreach-health` are watched twice — as the job that produced this morning's `job-failed`, and as an agent the watchdog independently scans — so a fresh re-check of their run history re-finds the SAME still-failed run and, being a different family (`agent-*` vs `job-failed`), landed unmatched in New even while the job-failed row above it was already Sorted or can't-say for the exact same event. Fixed with a post-pass after the main loop: a stored `job-failed{site-health|outreach-health}` or `snapshot-unsaved` drops its watchdog twin (`agent-failed`/`agent-degraded` on that agent; `snapshot-unsaved` only covers `agent-degraded{site-health}`) from `new`, never from `stillNeedsYou`. `job-failed{expiry-sweep}` is untouched — left not-re-checkable, as before. (b) `evaluateOutreach` returns at most one `engine-*` finding at a time, so errors-turned-stale between 07:00 and the press read as Sorted "sender is moving again" plus a New stale row — two reports of one unresolved condition. Fixed: `family()` groups every `engine-*` key together (subject-less, so `sameThing` then matches on family alone); `stranded-approved` stays its own family. (c) `calendar-unavailable` and `calendar-partial` are the same calendar read reported two ways, but had two different "families" and so could never match each other — a flip between them read as a false Sorted plus a New row. Fixed: both share family `calendar`, and `sameThing` matches either direction whenever either side is `calendar-unavailable`, regardless of subject; partial-vs-partial still goes by subject (unchanged). (d) When the sites check itself fails wholesale on a press with a stored `snapshot-unsaved` and nothing saved since 07:00, the snapshot route re-emitted "I checked the sites but couldn't save the result." as if sites had been checked — a fabricated fresh read standing in for a check that never ran. Fixed: that route now checks `checkFailed.sites` first and emits the ordinary `couldnt-check` row for `sites` instead, which also covers the standalone sites line so it isn't doubled.
22. **The press's two writes are deadline-bounded** (feature review D-II). `saveHealthSnapshot` in `debriefRead.ts` and `saveLastDebrief` in `debriefDoor.ts` run inside `withDeadline`, so a stuck write can't run the press past `maxDuration` and lose its AgentRun row; a timed-out `saveLastDebrief` reads as `saved: false`. `readDebriefChecks` itself is now pinned by tests (settings unreadable, pending count unreadable, no since-then read without a baseline).
23. **(D7, commit 9b769ae)** A Debrief taken before `PUSH_EXPECTED_HOUR` gives way to the morning's own state once it is 07:00 or later, so a 02:00 press can never hide a missing, failed, undelivered, unsaved or skipped 07:00 run (no silent failure). Inside the panel, "← Debrief" still reaches it.
24. **(D8, commits f6b1854 + this one)**
    - The island is keyed on the day too (`sentAtIso|todayKey(now)`), so the copy kept from a press yesterday can't return after an overnight resume. A panel left open across midnight closes on its next refresh.
    - The Debrief view is built first, and a view that fails to build passes `debrief: null` to the line, so the line always matches what can open.
    - The full-screen greeting keeps S21's rule: never for `unsaved`, and through a Debrief line only when today's Briefing exists. Deviation 7 widens the panel only.
    - A successful press moves focus to the heading.

export const DEBRIEF_AFTERNOON_OPENERS = ["Afternoon, Riku.", "Good afternoon, Riku.", "Riku, afternoon check-in."] as const;

export const DEBRIEF_EVENING_OPENERS = ["Evening, Riku.", "Good evening, Riku."] as const;

/** Approved by Riku 2026-10-11 (spec §10 item 2). */
export const DEBRIEF_NIGHT_OPENERS = ["Still up, Riku?", "Late one, Riku."] as const;

export type DebriefTimeBucket = "morning" | "afternoon" | "evening" | "night";

/** 05:00–11:59 morning · 12:00–16:59 afternoon · 17:00–20:59 evening · 21:00–04:59 night. `hour` is APP_TZ's. */
export function debriefTimeBucket(hour: number): DebriefTimeBucket {
  if (hour >= 5 && hour < 12) return "morning";
  if (hour >= 12 && hour < 17) return "afternoon";
  if (hour >= 17 && hour < 21) return "evening";
  return "night";
}

/**
 * The Debrief's opener: by day (pickLine's coprime step, so never the same
 * line two days running within a bucket) and by which pool the hour selects.
 * The morning bucket reuses the 07:00 any-day pool under its own salt.
 */
export function debriefOpener(day: DayKey, hour: number): string {
  switch (debriefTimeBucket(hour)) {
    case "morning":
      return pickLine(ANY_DAY_OPENERS, day, "debrief-morning");
    case "afternoon":
      return pickLine(DEBRIEF_AFTERNOON_OPENERS, day, "debrief-afternoon");
    case "evening":
      return pickLine(DEBRIEF_EVENING_OPENERS, day, "debrief-evening");
    case "night":
      return pickLine(DEBRIEF_NIGHT_OPENERS, day, "debrief-night");
  }
}

export const DEBRIEF_TAIL = "Here's where things stand.";

/** The panel's heading over a Debrief: opener + the fixed tail. Push-form; the page curls it. */
export function debriefHeading(day: DayKey, hour: number): string {
  return `${debriefOpener(day, hour)} ${DEBRIEF_TAIL}`;

 * `row.briefing` as a `StoredBriefing`, or null when it isn't one. `.lean()`
 * validates nothing on the way out and applies no schema defaults, so a
 * record saved before `omitted` existed (Plan B) carries no such key; it

function toBriefing(raw: unknown): StoredBriefing | null {

        subject: typeof (s as { subject?: unknown }).subject === "string" ? s.subject : null,

/**
 * lastDebrief.ts — access layer for the latest Debrief (S22). Mirrors
 * lastDigest.ts exactly (R55): the read is a findOne on the fixed id and never
 * an upsert, so a page view is never a write (R37); a missing document reads
 * as null, not as schema defaults, because a Debrief never taken is a fact;
 * a stored document whose `at` is not a Date reads as null too (throwing is
 * worse than absence). The upsert belongs to the write path only.
 *
 * Callers must have connectDB()'d already — same convention as the rest of the
 * lib layer.
 */

import LastDebrief, { DEBRIEF_ID } from "@/models/LastDebrief";
import type {
  DebriefRecord,
  StoredDebrief,
  StoredDebriefSymptom,
  StoredSortedItem,
  StoredStandaloneLine,
  StoredSymptom,
} from "@/lib/briefingTypes";

// Typed against DebriefRecord so a new field on the interface must FAIL TO
// COMPILE here rather than stay out of the projection and read as absent
// forever — getHealthSnapshot()'s pattern.
const DEBRIEF_PROJECTION: Record<keyof DebriefRecord, 1> & { _id: 0 } = {
  at: 1,
  baselineSentAt: 1,
  title: 1,
  sorted: 1,
  stillNeedsYou: 1,
  new: 1,
  now: 1,
  standaloneCouldntCheck: 1,
  since: 1,
  today: 1,
  freelance: 1,
  off: 1,
  unrecognised: 1,
  couldntCheck: 1,
  _id: 0,
};

function list<T>(value: unknown): T[] {
  return Array.isArray(value) ? (value as T[]) : [];
}

/** .lean() applies no defaults: an absent subject reads as null, never undefined. */
function withSubject<T extends { subject?: unknown }>(row: T): T & { subject: string | null } {
  return { ...row, subject: typeof row.subject === "string" ? row.subject : null };
}

/** findOne on the fixed id. NEVER upserts. null when absent (R55). `saved` is true: it was read back. */
export async function getLastDebrief(): Promise<StoredDebrief | null> {
  const doc = await LastDebrief.findOne({ _id: DEBRIEF_ID }, DEBRIEF_PROJECTION).lean();
  if (!doc) return null;

  const row = doc as unknown as Partial<Record<keyof DebriefRecord, unknown>>;
  if (!(row.at instanceof Date)) return null;
  const cc = (typeof row.couldntCheck === "object" && row.couldntCheck !== null ? row.couldntCheck : {}) as Partial<
    Record<"sites" | "watchdog" | "shikkstracker", unknown>
  >;

  return {
    at: row.at,
    baselineSentAt: row.baselineSentAt instanceof Date ? row.baselineSentAt : null,
    title: typeof row.title === "string" ? row.title : "",
    sorted: list<StoredSortedItem>(row.sorted).map(withSubject),
    stillNeedsYou: list<StoredDebriefSymptom>(row.stillNeedsYou).map((s) => ({
      ...withSubject(s),
      note: typeof s.note === "string" ? s.note : null,
    })),
    new: list<StoredSymptom>(row.new).map(withSubject),
    now: list<StoredSymptom>(row.now).map(withSubject),
    standaloneCouldntCheck: list<StoredStandaloneLine>(row.standaloneCouldntCheck),
    since: list<unknown>(row.since).filter((line): line is string => typeof line === "string"),
    today: typeof row.today === "string" ? row.today : "",
    freelance: typeof row.freelance === "string" ? row.freelance : null,
    off: typeof row.off === "string" ? row.off : null,
    unrecognised: typeof row.unrecognised === "number" ? row.unrecognised : 0,
    couldntCheck: { sites: cc.sites === true, watchdog: cc.watchdog === true, shikkstracker: cc.shikkstracker === true },
    saved: true,
  };
}

/**
 * Overwritten whole. One retry on E11000 (the losing side of the first-write
 * race, R55), then it throws. The fields are copied by name, so a caller that
 * hands in a StoredDebrief can never write the response-only `saved`.
 * runValidators makes the schema's bounds real on this path.
 *
 * NOT wrapped here: the door catches it, because a helper that swallows its
 * own failure cannot be tested for failing.
 */
export async function saveLastDebrief(d: DebriefRecord): Promise<void> {
  const record: DebriefRecord = {
    at: d.at,
    baselineSentAt: d.baselineSentAt,
    title: d.title,
    sorted: d.sorted,
    stillNeedsYou: d.stillNeedsYou,
    new: d.new,
    now: d.now,
    standaloneCouldntCheck: d.standaloneCouldntCheck,
    since: d.since,
    today: d.today,
    freelance: d.freelance,
    off: d.off,
    unrecognised: d.unrecognised,
    couldntCheck: d.couldntCheck,
  };
  const write = () =>
    LastDebrief.findOneAndUpdate(
      { _id: DEBRIEF_ID },
      { $set: record },
      { upsert: true, setDefaultsOnInsert: true, runValidators: true },
    );

  try {
    await write();
  } catch (err) {
    if ((err as { code?: unknown } | null)?.code !== 11000) throw err;
    await write();
  }
}

/**
 * debriefCompare.ts — this morning's stored symptoms against a fresh re-check
 * (S22, spec §3.5). Pure: no database, no network, no clock (`now` is a
 * parameter). Imports are pure modules or `import type` only.
 *
 * Every stored symptom lands in exactly one place, decided in this order:
 *   1. snapshot-unsaved   → its own rule: did a snapshot save since 07:00?
 *   2. not re-checkable   → Still needs you, verbatim: unstuck-items, the
 *                           expiry sweep's job-failed, and a job-failed saved
 *                           before `subject` existed (plan deviation 2)
 *   3. its source failed  → Still needs you, with that source's can't-say note
 *   4. otherwise          → a fresh problem about the same thing? Still needs
 *                           you, re-explained from the FRESH problem : Sorted
 * Every fresh problem nothing claimed is New. A failed source with no
 * can't-say row of its own gets one standalone line instead (spec §3.4).
 *
 * "The same thing" (plan deviation 1): sites and agents match by FAMILY and
 * subject — one site yields at most one site-* problem and one agent at most
 * one agent-* anomaly, so a site that went from error 503 to timing out is
 * still down, never "back up". Every other key matches exactly.
 *
 * Step 3 runs before step 4, so a symptom reaching step 4 comes from a source
 * that answered on this press: "not found" there is a true success, never a
 * masked failure.
 *
 * Words here are push-form (straight apostrophes); the page curls them.
 */

import { APP_TZ } from "@/lib/constants";
import { dayKey, todayKey } from "@/lib/days";
import { explain } from "@/lib/causes";
import { AGENT_NAMES, subjectOf, type Problem } from "@/lib/problems";
import { capWord } from "@/lib/voice";
import {
  DEBRIEF_SOURCES,
  type DebriefSource,
  type ProblemKey,
  type StoredBold,
  type StoredSymptom,
} from "@/lib/briefingTypes";
import type { StoredDigest } from "@/lib/lastDigest";
import type { Agent } from "@/models/AgentRun";

export type SourceFlags = Record<DebriefSource, boolean>;

/** Today's 07:00 Briefing, flattened to its symptoms in report order. */
export interface Baseline {
  sentAt: Date;
  symptoms: StoredSymptom[];
}

/** When a HealthSnapshot last saved (null = never), and whether this press's own save just failed. */
export interface SnapshotState {
  checkedAt: Date | null;
  ownSaveJustFailed: boolean;
}

export interface SortedRow {
  key: ProblemKey;
  subject: string | null;
  sentence: string;
}

export type StillRow =
  /** Re-checked and still there: explained from the fresh problem. */
  | { kind: "fresh"; problem: Problem }
  /** Not re-checkable: exactly as stored at 07:00. */
  | { kind: "verbatim"; symptom: StoredSymptom }
  /** Its source couldn't be checked: as stored at 07:00, plus that source's note. */
  | { kind: "couldnt-check"; symptom: StoredSymptom; source: DebriefSource };

export interface DebriefComparison {
  sorted: SortedRow[];
  stillNeedsYou: StillRow[];
  new: Problem[];
  /** The no-baseline flat list (D5); empty whenever a baseline exists. */
  now: Problem[];
  /** One per failed source with no can't-say row to attach to, in DEBRIEF_SOURCES order. */
  standaloneCouldntCheck: DebriefSource[];
  couldntCheck: SourceFlags;
}

/** The can't-say note under a stored symptom whose source failed on this press (spec §10 item 4, approved). */
export const CANT_SAY: Readonly<Record<DebriefSource, string>> = Object.freeze({
  sites: "I couldn't check your sites just now, so I can't say whether that's sorted.",
  watchdog: "I couldn't check the run history just now, so I can't say whether that's sorted.",
  shikkstracker: "I couldn't reach ShikksTracker just now, so I can't say whether that's sorted.",
});

/** The standalone line for a failed source with nothing from it this morning (spec §10 item 4a, approved). */
export const STANDALONE: Readonly<Record<DebriefSource, string>> = Object.freeze({
  sites: "I couldn't check your sites just now.",
  watchdog: "I couldn't check the run history just now.",
  shikkstracker: "I couldn't reach ShikksTracker just now.",
});

/**
 * Today's 07:00 Briefing as the baseline, or null (D5): no digest, one from
 * another APP_TZ day, or one saved without a structured Briefing (plan
 * deviation 8). A morning that reached no device still counts — it was saved.
 */
export function baselineFromDigest(digest: StoredDigest | null, now: Date): Baseline | null {
  if (digest === null || digest.briefing === null) return null;
  if (dayKey(digest.sentAt, APP_TZ) !== todayKey(now)) return null;
  return { sentAt: digest.sentAt, symptoms: digest.briefing.stories.flatMap((story) => story.symptoms) };
}

type Route =
  | { kind: "source"; source: DebriefSource }
  | { kind: "plain" }
  | { kind: "not-re-checkable" }
  | { kind: "snapshot" };

function isAgent(subject: string | null): subject is Agent {
  return subject !== null && Object.prototype.hasOwnProperty.call(AGENT_NAMES, subject);
}

/** Which source re-checks a stored symptom (spec §3.5's table). */
function routeOf(s: StoredSymptom): Route {
  switch (s.key) {
    case "site-status":
    case "site-timeout":
    case "site-unreachable":
      return { kind: "source", source: "sites" };
    case "agent-never-ran":
    case "agent-stale":
    case "agent-failed":
    case "agent-degraded":
      return { kind: "source", source: "watchdog" };
    case "job-failed":
      if (s.subject === "watchdog") return { kind: "source", source: "watchdog" };
      if (s.subject === "site-health") return { kind: "source", source: "sites" };
      if (s.subject === "outreach-health") return { kind: "source", source: "shikkstracker" };
      // The expiry sweep never runs here; a subject-less job-failed can't be placed.
      return { kind: "not-re-checkable" };
    case "snapshot-unsaved":
      return { kind: "snapshot" };
    case "unstuck-items":
      return { kind: "not-re-checkable" };
    case "engine-never-ran":
    case "engine-unreadable":
    case "engine-stale":
    case "engine-errors":
    case "stranded-approved":
    case "pipeline-unavailable":
      return { kind: "source", source: "shikkstracker" };
    case "calendar-unavailable":
    case "calendar-partial":
    case "todos-unavailable":
      // No wholesale flag: a failed re-read is itself a fresh calendar/to-do problem.
      return { kind: "plain" };
  }
}

function family(key: ProblemKey): string {
  if (key.startsWith("site-")) return "site";
  if (key.startsWith("agent-")) return "agent";
  return key;
}

/** The text of the first bold range — the catalogue always bolds the subject first ("Meowchi's site", "The chaser"). */
function leadText(text: string, bold: readonly StoredBold[]): string | null {
  const first = bold[0];
  if (first === undefined || first.start < 0 || first.end > text.length || first.start >= first.end) return null;
  return text.slice(first.start, first.end);
}

/** Is this fresh problem about the same thing as this stored symptom? */
function sameThing(stored: StoredSymptom, fresh: Problem): boolean {
  if (family(stored.key) !== family(fresh.key)) return false;
  const subject = subjectOf(fresh);
  if (stored.subject !== null) return stored.subject === subject;
  // A key with no subject is one condition: the family (= the key) is enough.
  if (subject === null) return true;
  // Saved before `subject` existed (plan deviation 2). A partial calendar
  // outage is one condition per morning, whatever names it lists.
  if (fresh.key === "calendar-partial") return true;
  const storedLead = leadText(stored.sentence, stored.bold);
  const explained = explain(fresh).sentence;
  const freshLead = leadText(explained.text, explained.bold);
  return storedLead !== null && freshLead !== null && storedLead.toLowerCase() === freshLead.toLowerCase();
}

/** The fixed Sorted sentence per key (spec §4.2, §10 item 3 — approved). */
function sortedSentence(s: StoredSymptom): string {
  switch (s.key) {
    case "site-status":
    case "site-timeout":
    case "site-unreachable": {
      const name = s.subject !== null ? `${s.subject}'s site` : (leadText(s.sentence, s.bold) ?? "That site");
      return `${name} is back up.`;
    }
    case "agent-never-ran":
    case "agent-stale":
    case "agent-failed":
    case "agent-degraded": {
      const name = isAgent(s.subject) ? capWord(AGENT_NAMES[s.subject]) : (leadText(s.sentence, s.bold) ?? "That job");
      return `${name} is running again.`;
    }
    case "job-failed": {
      const name = isAgent(s.subject) ? capWord(AGENT_NAMES[s.subject]) : "That check";
      return `${name} ran clean just now.`;
    }
    case "snapshot-unsaved":
      return "Today's site check is saved now.";
    case "engine-never-ran":
    case "engine-unreadable":
    case "engine-stale":
    case "engine-errors":
    case "stranded-approved":
      return "ShikksTracker's sender is moving again.";
    case "pipeline-unavailable":
      return "I can reach ShikksTracker again.";
    case "calendar-unavailable":
    case "calendar-partial":
      return "Your calendar's answering again.";
    case "todos-unavailable":
      return "I can read your to-dos again.";
    case "unstuck-items":
      // Never reached: routeOf sends unstuck-items to Still needs you,
      // verbatim, before a sorted sentence is ever asked for (pinned by test).
      throw new Error("unstuck-items is never re-checked, so it is never sorted");
  }
}

/**
 * The comparison (spec §3.5). `fresh` never contains job-failed or
 * pipeline-unavailable (debrief.ts's freshProblems can't produce them); if one
 * ever slipped through it would still resolve — matched like any other key,
 * or New — rather than crash.
 */
export function compareToBaseline(
  baseline: Baseline | null,
  fresh: Problem[],
  snapshot: SnapshotState,
  checkFailed: SourceFlags,
): DebriefComparison {
  const couldntCheck: SourceFlags = { ...checkFailed };
  const failedSources = DEBRIEF_SOURCES.filter((s) => checkFailed[s]);

  if (baseline === null) {
    return { sorted: [], stillNeedsYou: [], new: [], now: [...fresh], standaloneCouldntCheck: failedSources, couldntCheck };
  }

  const used = new Set<number>();
  const take = (matches: (p: Problem) => boolean): Problem | null => {
    const i = fresh.findIndex((p, j) => !used.has(j) && matches(p));
    if (i === -1) return null;
    used.add(i);
    return fresh[i];
  };

  const sorted: SortedRow[] = [];
  const stillNeedsYou: StillRow[] = [];

  for (const s of baseline.symptoms) {
    const route = routeOf(s);

    if (route.kind === "snapshot") {
      // This press's own save failure (if any) is consumed here, so it is never New as well.
      const own = take((p) => p.key === "snapshot-unsaved");
      const savedSince = snapshot.checkedAt !== null && snapshot.checkedAt.getTime() > baseline.sentAt.getTime();
      if (!snapshot.ownSaveJustFailed && savedSince) {
        sorted.push({ key: s.key, subject: s.subject, sentence: sortedSentence(s) });
      } else {
        stillNeedsYou.push({ kind: "fresh", problem: own ?? { key: "snapshot-unsaved" } });
      }
      continue;
    }

    if (route.kind === "not-re-checkable") {
      stillNeedsYou.push({ kind: "verbatim", symptom: s });
      continue;
    }

    if (route.kind === "source" && checkFailed[route.source]) {
      stillNeedsYou.push({ kind: "couldnt-check", symptom: s, source: route.source });
      continue;
    }

    const match = take((p) => sameThing(s, p));
    if (match !== null) stillNeedsYou.push({ kind: "fresh", problem: match });
    else sorted.push({ key: s.key, subject: s.subject, sentence: sortedSentence(s) });
  }

  const covered = new Set(stillNeedsYou.flatMap((row) => (row.kind === "couldnt-check" ? [row.source] : [])));
  return {
    sorted,
    stillNeedsYou,
    new: fresh.filter((_, j) => !used.has(j)),
    now: [],
    standaloneCouldntCheck: failedSources.filter((s) => !covered.has(s)),
    couldntCheck,
  };
}

/**
 * debrief.ts — the Debrief, composed (S22, spec §3.4, §4, §5). Pure: no
 * database, no network, no clock (`now` is a parameter). Imports are pure
 * modules or `import type` only.
 *
 * FRESH PROBLEMS come only from each source's own SUCCESSFUL outcome, through
 * problems.ts's per-source translators — never through buildProblems. A
 * source that fails wholesale (sites, the run history, ShikksTracker) produces
 * no Problem at all and sets its couldntCheck flag instead, so a Debrief can
 * never say "{Job} broke this morning." at 13:00, and one outage is never
 * reported twice (spec §3.4). Calendar and to-do failures are their own
 * findings and go in as the push takes them (digest.ts todayProblems).
 *
 * THE RECORD keeps exactly one side live (spec §5.1): with a baseline,
 * sorted/stillNeedsYou/new/since; without one, now. Standalone couldn't-check
 * lines are independent of that split.
 *
 * Strings stored are push-form, except `since` (sinceThenLines curls).
 */

import { APP_TZ } from "@/lib/constants";
import { clockHHMM, dayKey, todayKey } from "@/lib/days";
import { explain } from "@/lib/causes";
import { fromAnomaly, fromFinding, fromSite, type Problem } from "@/lib/problems";
import {
  boundText,
  composeTodayLine,
  freelanceLine,
  offLine,
  todayProblems,
  toStoredSymptom,
  type DigestTodayInput,
} from "@/lib/digest";
import { sinceThenLines, type SinceThenInput } from "@/lib/sinceThen";
import { numberWord } from "@/lib/voice";
import {
  BRIEFING_BOUNDS,
  DEBRIEF_BOUNDS,
  DEBRIEF_SOURCES,
  type DebriefRecord,
  type StoredDebrief,
  type StoredDebriefSymptom,
  type StoredSortedItem,
  type StoredSymptom,
} from "@/lib/briefingTypes";
import { CANT_SAY, STANDALONE, compareToBaseline, type Baseline, type SourceFlags, type StillRow } from "@/lib/debriefCompare";
import type { Anomaly, LatestRun } from "@/lib/watchdog";
import type { SiteResult } from "@/lib/siteHealth";
import type { OutreachFinding } from "@/lib/outreachHealth";

/** What one press read (debriefRead.ts). Each source is caught on its own. */
export interface DebriefOutcomes {
  /** The run history: the watchdog's verdicts, and the runs themselves (for New-row times). */
  watchdog: { ok: true; anomalies: Anomaly[]; runs: LatestRun[] } | { ok: false };
  /**
   * The three sites, fresh or reused inside the 60-second floor. `savedAt` is
   * when a HealthSnapshot last SAVED (this press's, or the reused one's, or
   * the last good one when this press's save failed); null = never.
   */
  sites:
    | { ok: true; results: SiteResult[]; savedAt: Date | null; ownSaveJustFailed: boolean }
    | { ok: false; savedAt: Date | null };
  /** ShikksTracker: summary AND attention — either one failing fails the source (spec §3.5). */
  shikkstracker:
    | { ok: true; findings: OutreachFinding[]; attention: { repliedUnanswered: number; overdue: number } }
    | { ok: false };
  today: DigestTodayInput;
  pending: number | "unavailable";
  chaserEnabled: boolean | "unavailable";
  /** Since-then reads against the baseline's sentAt; null with no baseline (or if they failed). */
  since: SinceThenInput | null;
}

/** The fresh problem list (spec §3.4). Never contains job-failed or pipeline-unavailable. */
export function freshProblems(o: DebriefOutcomes): Problem[] {
  const problems: Problem[] = [];
  if (o.watchdog.ok) for (const a of o.watchdog.anomalies) problems.push(fromAnomaly(a));
  if (o.sites.ok) for (const s of o.sites.results) if (!s.up) problems.push(fromSite(s));
  if (o.shikkstracker.ok) for (const f of o.shikkstracker.findings) problems.push(fromFinding(f));
  if (o.sites.ok && o.sites.ownSaveJustFailed) problems.push({ key: "snapshot-unsaved" });
  problems.push(...todayProblems(o.today));
  return problems;
}

/** The greeting-line text (spec §2.2, §10 item 1). Push-form. At most DEBRIEF_BOUNDS.title. */
export function debriefTitle(at: Date, outstanding: number): string {
  const stamp = clockHHMM(at, APP_TZ);
  if (outstanding === 0) return `Debrief at ${stamp}: all clear.`;
  if (outstanding === 1) return `Debrief at ${stamp}: one thing still needs you.`;
  return `Debrief at ${stamp}: ${numberWord(outstanding)} things still need you.`;
}

/**
 * A New row's sentence with the time its run happened (spec §4.2, plan
 * deviation 6): only agent-failed / agent-degraded, only for a run that
 * started today. Bold ranges are at the start of the sentence, so they stay
 * valid; a sentence that would overrun its bound is left as it was.
 */
function stamped(stored: StoredSymptom, p: Problem, runs: readonly LatestRun[], now: Date): StoredSymptom {
  if (p.key !== "agent-failed" && p.key !== "agent-degraded") return stored;
  const run = runs.find((r) => r.agent === p.agent);
  if (run === undefined || dayKey(run.startedAt, APP_TZ) !== todayKey(now)) return stored;
  if (!stored.sentence.endsWith(".")) return stored;
  const sentence = `${stored.sentence.slice(0, -1)} at ${clockHHMM(run.startedAt, APP_TZ)}.`;
  return sentence.length > BRIEFING_BOUNDS.symptomSentence ? stored : { ...stored, sentence };
}

function storeStill(row: StillRow): StoredDebriefSymptom {
  switch (row.kind) {
    case "fresh":
      return { ...toStoredSymptom(row.problem), note: null };
    case "verbatim":
      return { ...row.symptom, note: null };
    case "couldnt-check":
      return { ...row.symptom, note: CANT_SAY[row.source] };
  }
}

/** Sorted lines, each sentence once (plan deviation 12), bounded. */
function storeSorted(rows: ReadonlyArray<{ key: StoredSortedItem["key"]; subject: string | null; sentence: string }>): StoredSortedItem[] {
  const seen = new Set<string>();
  const out: StoredSortedItem[] = [];
  for (const r of rows) {
    if (seen.has(r.sentence)) continue;
    seen.add(r.sentence);
    out.push({ key: r.key, subject: r.subject, sentence: boundText(r.sentence, DEBRIEF_BOUNDS.sortedSentence) });
  }
  return out;
}

export interface DebriefBuildInput {
  now: Date;
  outcomes: DebriefOutcomes;
  baseline: Baseline | null;
}

/** The Debrief, ready to store (spec §5.1). Pure; the door saves it last. */
export function buildDebrief({ now, outcomes: o, baseline }: DebriefBuildInput): DebriefRecord {
  const fresh = freshProblems(o);
  const checkFailed: SourceFlags = { sites: !o.sites.ok, watchdog: !o.watchdog.ok, shikkstracker: !o.shikkstracker.ok };
  const snapshot = { checkedAt: o.sites.savedAt, ownSaveJustFailed: o.sites.ok && o.sites.ownSaveJustFailed };
  const cmp = compareToBaseline(baseline, fresh, snapshot, checkFailed);
  const runs = o.watchdog.ok ? o.watchdog.runs : [];

  // Counted before any bound slices a list (A-II's rule), and including the
  // standalone lines and the no-baseline list: "all clear" is never said over
  // a source that couldn't be checked (plan deviation 5).
  const outstanding = cmp.stillNeedsYou.length + cmp.new.length + cmp.now.length + cmp.standaloneCouldntCheck.length;

  const freelance = freelanceLine({
    attention: o.shikkstracker.ok ? o.shikkstracker.attention : null,
    pending: o.pending === "unavailable" ? 0 : o.pending,
  });
  const off = o.chaserEnabled === "unavailable" ? null : offLine(o.chaserEnabled ? [] : ["chaser"]);

  return {
    at: now,
    baselineSentAt: baseline === null ? null : baseline.sentAt,
    title: debriefTitle(now, outstanding),
    sorted: storeSorted(cmp.sorted).slice(0, DEBRIEF_BOUNDS.sorted),
    stillNeedsYou: cmp.stillNeedsYou.slice(0, DEBRIEF_BOUNDS.stillNeedsYou).map(storeStill),
    new: cmp.new.slice(0, DEBRIEF_BOUNDS.newProblems).map((p) => stamped(toStoredSymptom(p), p, runs, now)),
    now: cmp.now.slice(0, DEBRIEF_BOUNDS.now).map((p) => toStoredSymptom(p)),
    standaloneCouldntCheck: cmp.standaloneCouldntCheck
      .slice(0, DEBRIEF_BOUNDS.standalone)
      .map((source) => ({ source, sentence: STANDALONE[source] })),
    since:
      baseline !== null && o.since !== null
        ? sinceThenLines(o.since, baseline.sentAt, now)
            .slice(0, DEBRIEF_BOUNDS.since)
            .map((line) => boundText(line, DEBRIEF_BOUNDS.sinceLine))
        : [],
    today: boundText(composeTodayLine(o.today), DEBRIEF_BOUNDS.today),
    freelance: freelance === null ? null : boundText(freelance, DEBRIEF_BOUNDS.freelance),
    off: off === null ? null : boundText(off, DEBRIEF_BOUNDS.off),
    // Over every fresh problem (A-II's rule). None carries a raw error today,
    // so this is 0 in practice; it is counted so a future source with one is.
    unrecognised: fresh.filter((p) => explain(p).causeKey === "unrecognised").length,
    couldntCheck: checkFailed,
  };
}

/** How many sources couldn't be checked: each is a failed item on the run row (spec §3.4). */
export function countCouldntCheck(d: Pick<DebriefRecord, "couldntCheck">): number {
  return DEBRIEF_SOURCES.filter((s) => d.couldntCheck[s]).length;
}

/** The door's response: the stored Debrief plus the response-only `saved` (spec §3.1). */
export function toDebriefResponse(d: DebriefRecord, saved: boolean = true): StoredDebrief {
  return { ...d, saved };
}

 * debriefRead.ts — the Debrief's fresh checks (S22, spec §3.3). Impure.
 *
 * Shaped like sinceThenRead.ts and digestToday.ts: every read is independent,
 * bounded (MONGO_READ_TIMEOUT_MS for Mongo; ST_TIMEOUT_MS / SITE_TIMEOUT_MS /
 * Google's per-layer timeout inside the reused readers) and caught into its
 * own outcome, so one slow or failed read never costs the others.
 * readDebriefChecks never throws, and its legs run in parallel: the press
 * costs the slowest leg, not the sum.
 *
 * WRITES: exactly one, deliberately — saveHealthSnapshot, when "Check now"'s
 * 60-second floor doesn't apply, so the Freelance page's health strip picks
 * up the Debrief's own reading (spec §3.3). Inside the floor the stored
 * reading is reused and no client site is pinged twice. Nothing else is
 * written here: no queue change, no expiry, no notification, nothing sent.
 * Settings come through readOsSettings (R37), never the upserting accessor.
 *
 * Callers must have connectDB()'d already — the same convention as the rest
 * of the lib layer (readSinceThen connects for itself).

/**
 * The three sites. Inside CHECK_FLOOR_MS the stored reading is reused, exactly
 * as POST /api/health/sites does, so a Debrief pressed right after "Check
 * now" (or the reverse) never pings a client's site twice. Otherwise a fresh
 * check, saved to HealthSnapshot. `savedAt` is when a snapshot last SAVED —
 * the reused one's, this press's, or (when this press's save failed) the last
 * good one — which snapshot-unsaved's recheck reads (spec §3.5).
 */
export async function readSitesForDebrief(): Promise<DebriefOutcomes["sites"]> {
  let existing: StoredHealth | null = null;
  try {
    existing = await bounded(getHealthSnapshot(), "snapshot read");
  } catch (err) {
    console.error("[debrief] snapshot read failed, checking the sites fresh:", err);
  }
  if (existing !== null && isWithinCheckFloor(new Date(), existing.checkedAt)) {
    return { ok: true, results: existing.sites, savedAt: existing.checkedAt, ownSaveJustFailed: false };
  }

  const lastSavedAt = existing === null ? null : existing.checkedAt;
  let results: SiteResult[];
  try {
    results = await checkSites();
  } catch (err) {
    console.error("[debrief] site check failed:", err);
    return { ok: false, savedAt: lastSavedAt };
  }

  // The moment the reading was taken — after the checks resolve (saveHealthSnapshot's contract).
  const checkedAt = new Date();
  try {
    await saveHealthSnapshot(checkedAt, results);
    return { ok: true, results, savedAt: checkedAt, ownSaveJustFailed: false };
  } catch (err) {
    console.error("[debrief] snapshot write failed:", err);
    return { ok: true, results, savedAt: lastSavedAt, ownSaveJustFailed: true };
  }
}

/** Every fresh check a press makes (spec §3.3), in parallel. Never throws. */
export async function readDebriefChecks(now: Date, baselineSentAt: Date | null): Promise<DebriefOutcomes> {

    console.error("[debrief] settings read failed:", err);
    return null;
  });

  const [watchdog, sites, shikkstracker, today, pending, since, settingsValue] = await Promise.all([
    readWatchdogForDebrief(now),
    readSitesForDebrief(),
    settings.then((s) => readShikksTrackerForDebrief(now, s === null ? OS_SETTINGS_DEFAULTS.chaserNDays : s.chaserNDays)),
    settings.then((s) => readTodayForDebrief(s, day)),

      console.error("[debrief] pending count failed:", err);
      return "unavailable";

    baselineSentAt === null

      : readSinceThen(baselineSentAt, now).catch((err: unknown): null => {
          console.error("[debrief] since-then read failed:", err);
          return null;
        }),
    settings,
  ]);

  return {
    watchdog,
    sites,
    shikkstracker,
    today,
    pending,
    chaserEnabled: settingsValue === null ? "unavailable" : settingsValue.chaserEnabled,
    since,
  };
}

/**
 * debriefDoor.ts — one press of "Debrief now" (S22, spec §3.1). The route is
 * three lines around this, so the behaviour is here, where a test can reach
 * it (plan deviation 11).
 *
 *   connectDB fails          → typed 500, no AgentRun row (there is nowhere to
 *                              write one; the morning route behaves the same)
 *   a Debrief < 1 min old    → that same document, no re-check, no run row:
 *                              nothing happened, so nothing is recorded
 *   otherwise                → one runJob("debrief") row: baseline, checks,
 *                              build, and the save LAST; a failed save still
 *                              answers (saved: false) and is a failed item
 *   the job throws           → typed 500 (its run row says why); nothing saved
 *
 * A failed CACHE READ is not a failed Debrief: it means "nothing to reuse"
 * and falls through to a real build. Site only: this door sends nothing
 * outward, drafts nothing, approves nothing and never expires the queue — the
 * 07:00 sweep stays the only place stale items expire.
 *
 * Two devices pressing in the same second both build, and the last write
 * wins — this app's standing convention for an overwritten-whole singleton
 * (spec §3.1: accepted, no guard).
 */

import { connectDB } from "@/lib/db";
import { runJob } from "@/lib/jobs/runJob";
import { DEBRIEF_CACHE_MS } from "@/lib/constants";
import { MONGO_READ_TIMEOUT_MS, withDeadline } from "@/lib/deadline";
import { isWithinCheckFloor } from "@/lib/healthSnapshot";
import { getLastDebrief, saveLastDebrief } from "@/lib/lastDebrief";
import { readDebriefChecks, readTodaysBaseline } from "@/lib/debriefRead";
import { buildDebrief, countCouldntCheck, toDebriefResponse } from "@/lib/debrief";
import type { StoredDebrief } from "@/lib/briefingTypes";

export type DebriefPress =
  | { status: 200; body: StoredDebrief }
  | { status: 500; body: { error: "debrief-failed" } };

const FAILED: DebriefPress = { status: 500, body: { error: "debrief-failed" } };

export async function pressDebrief(now: Date): Promise<DebriefPress> {
  try {
    await connectDB();
  } catch (err) {
    console.error("[api/briefing/debrief] connectDB failed:", err);
    return FAILED;
  }

  let existing: StoredDebrief | null = null;
  try {
    existing = await withDeadline(getLastDebrief(), MONGO_READ_TIMEOUT_MS, "debrief cache read");
  } catch (err) {
    console.error("[api/briefing/debrief] cache read failed, building fresh:", err);
  }
  // The same 60-second rule as the site floor, but its own constant (spec
  // §3.2). A future `at` (clock skew) is never "inside" it.
  if (existing !== null && isWithinCheckFloor(now, existing.at, DEBRIEF_CACHE_MS)) {
    return { status: 200, body: existing };
  }

  const result = await runJob("debrief", async () => {
    const baseline = await readTodaysBaseline(now);
    const outcomes = await readDebriefChecks(now, baseline === null ? null : baseline.sentAt);
    const debrief = buildDebrief({ now, outcomes, baseline });
    // Last: every read and every pure step is done, so a failure above this
    // line leaves nothing half-saved (spec §6).
    let saved = true;
    try {
      await saveLastDebrief(debrief);
    } catch (err) {
      saved = false;
      console.error("[api/briefing/debrief] save failed:", err);
    }
    return {
      counts: { itemsProcessed: 1, itemsFailed: (saved ? 0 : 1) + countCouldntCheck(debrief) },
      data: { debrief, saved },
    };
  });

  if (!result.ok || result.data === null) return FAILED;
  return { status: 200, body: toDebriefResponse(result.data.debrief, result.data.saved) };
}

    const still = rows(d.stillNeedsYou, "s");
    const fresh = rows(d.new, "n");
    const nothing = sorted.length === 0 && still.length === 0 && fresh.length === 0 && standalone.length === 0;
    comparison = {
      kind: "since",
      heading: `Since ${clockHHMM(d.baselineSentAt, APP_TZ)}`,
      sorted,
      still,
      fresh,
      standalone,
      allClear: nothing ? ALL_CLEAR_SAME : null,
    };
  }

  return {
    atIso: d.at.toISOString(),
    stamp,
    heading: toPage(debriefHeading(dayKey(d.at, APP_TZ), hour)),
    comparison,
    done: d.since.map(toPage),
    today: toPage(d.today),
    freelance: d.freelance === null ? null : toPage(d.freelance),
    off: d.off === null ? null : toPage(d.off),
  };
}

function isObject(v: unknown): v is Record<string, unknown> {
  return typeof v === "object" && v !== null && !Array.isArray(v);
}

function isoDate(v: unknown): Date | null {
  if (typeof v !== "string") return null;
  const d = new Date(v);
  return Number.isNaN(d.getTime()) ? null : d;
}

/**
 * The door's JSON back into a StoredDebrief (dates revived), or null when the
 * body isn't one. The top level is checked; rows are the door's own bounded
 * output and are taken as they come — the island builds the view inside a
 * try, so a malformed row reads as "didn't finish", never a crash.
 */
export function parseDebriefResponse(body: unknown): { debrief: StoredDebrief; saved: boolean } | null {
  if (!isObject(body)) return null;
  const at = isoDate(body.at);
  const baselineSentAt = body.baselineSentAt === null ? null : isoDate(body.baselineSentAt);
  if (at === null || (body.baselineSentAt !== null && baselineSentAt === null)) return null;
  if (typeof body.title !== "string" || typeof body.today !== "string" || typeof body.saved !== "boolean") return null;
  if (typeof body.unrecognised !== "number") return null;
  if (!(body.freelance === null || typeof body.freelance === "string")) return null;
  if (!(body.off === null || typeof body.off === "string")) return null;
  const lists = ["sorted", "stillNeedsYou", "new", "now", "standaloneCouldntCheck", "since"] as const;
  if (!lists.every((k) => Array.isArray(body[k]))) return null;
  const cc = isObject(body.couldntCheck) ? body.couldntCheck : {};

  return {
    saved: body.saved,
    debrief: {
      at,
      baselineSentAt,
      title: body.title,
      sorted: body.sorted as StoredSortedItem[],
      stillNeedsYou: body.stillNeedsYou as StoredDebriefSymptom[],
      new: body.new as StoredSymptom[],
      now: body.now as StoredSymptom[],
      standaloneCouldntCheck: body.standaloneCouldntCheck as StoredStandaloneLine[],
      since: (body.since as unknown[]).filter((line): line is string => typeof line === "string"),
      today: body.today,
      freelance: body.freelance,
      off: body.off,
      unrecognised: body.unrecognised,
      couldntCheck: { sites: cc.sites === true, watchdog: cc.watchdog === true, shikkstracker: cc.shikkstracker === true },
      saved: body.saved,
    },
  };
}

    // is already swallowed by onCancel's preventDefault, so nothing else
    // could ever close it again (principal review, round 2, item 2).
    try {
      await shrinkTo(dlg, lineRef.current?.getBoundingClientRect() ?? null);
    } finally {
      dlg.inert = false;
      closingMain.current = false;
    }
    dlg.close();
    setOpen(null);
    lineRef.current?.focus();
    if (wasFull && view !== null && view.isToday && !view.seen && !seenSent.current) {
      seenSent.current = true;
      // Fire and forget: a failure only means it may greet once more (spec §5.2).
      void fetch("/api/briefing/seen", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ sentAt: view.sentAtIso }),
        signal: AbortSignal.timeout(PRESS_TIMEOUT_MS),
      }).catch(() => {});
    }
  }

  function openCard(e: MouseEvent<HTMLButtonElement>, symptom: SymptomView) {
    cardFrom.current = e.currentTarget;
    setCard(symptom);
  }

  async function closeCard() {
    const c = cardRef.current;
    if (!c || !c.open || closingCard.current) return;
    closingCard.current = true;
    c.inert = true;
    try {
      await shrinkTo(c, cardFrom.current?.getBoundingClientRect() ?? null);
    } finally {
      c.inert = false;
      closingCard.current = false;
    }
    c.close();
    setCard(null);
    cardFrom.current?.focus();
  }

  return (
    <>
      <button
        ref={lineRef}
        type="button"
        className={`bf-line is-${line.tone}`}
        onClick={openPanel}
        disabled={!canOpen}
        aria-haspopup={canOpen ? "dialog" : undefined}
      >
        <i aria-hidden="true" />
        <span>{line.text}</span>
      </button>

      {/* onClose guards any native close that doesn't go through close()
          itself — e.g. a future change that calls dlg.close() directly —
          keeping `open` in sync with the dialog's actual state rather than
          React's. It is not a fix for view becoming null while open:
          removing a <dialog> from the DOM does not fire `close`, and an
          unmounted element drops its own handlers regardless; BriefingSlot
          keying this island on the Briefing's sentAtIso makes that scenario
          moot anyway (a new key remounts the component, so `open` comes
          fresh from its initialiser). close()'s own dlg.close() call fires
          this event too, so setOpen(null) there is a harmless repeat of
          what close() already does a few lines later (principal review,
          round 2, item 3). */}
      {(view !== null || shownDebrief !== null) && (
        <dialog
          ref={dlgRef}
          className={`bf-dialog ${open === "full" ? "is-full" : "is-panel"}`}
          aria-labelledby={titleId}
          onCancel={(e) => {
            e.preventDefault();
            void close();
          }}
          onClick={(e) => {
            if (e.target === e.currentTarget) void close();
          }}
          onClose={() => setOpen(null)}
        >
          <div className="bf-in">
            <header className="bf-head">
              <p className="bf-when">
                {debriefShown !== null
                  ? `Debrief · ${debriefShown.stamp}`
                  : morningShown !== null
                    ? `${morningShown.label} · ${morningShown.stamp}`
                    : ""}
              </p>
              <h2 id={titleId} ref={titleRef} tabIndex={-1} className="bf-title">
                {debriefShown !== null ? debriefShown.heading : (morningShown?.title ?? "")}
              </h2>
              <button type="button" className="bf-x" aria-label="Close" onClick={() => void close()}>
                ✕
              </button>
            </header>

            {debriefShown !== null && (
              <>
                {unsavedAt === debriefShown.atIso && (
                  <p className="bf-p bf-warn">I couldn’t save this one, so other devices won’t see it.</p>
                )}
                <DebriefBody d={debriefShown} onCard={openCard} />
                {view !== null && view.isToday && (
                  <button type="button" className="bf-swap" onClick={() => swapTo("morning")}>
                    This morning’s briefing →
                  </button>
                )}
              </>
            )}

            {morningShown !== null && (
              <>
                {open === "panel" && shownDebrief !== null && (
                  <button type="button" className="bf-swap" onClick={() => swapTo("debrief")}>
                    ← Debrief
                  </button>
                )}
                {morningShown.kind === "full" ? (
                  <>
                    {morningShown.stories.length > 0 && (
                      <section className="bf-sec">
                        <h3 className="bf-h">As of {morningShown.stamp}</h3>
                        <ul className="bf-stories">
                          {morningShown.stories.map((story) =>
                            story.symptoms.length === 1 ? (

                                <button type="button" className="bf-row" onClick={(e) => openCard(e, story.symptoms[0])}>

                                    <Said segments={story.sentence} />
                                  </span>
                                  <span className="bf-next">{story.symptoms[0].nextStep}</span>

                                <p className="bf-story">
                                  <Said segments={story.sentence} />
                                </p>
                                <ul className="bf-symptoms">

                                    <li key={s.id}>
                                      <button type="button" className="bf-row" onClick={(e) => openCard(e, s)}>
                                        <span className="bf-said">
                                          <Said segments={s.sentence} />

                    <section className="bf-sec">
                      <h3 className="bf-h">The day, as of {morningShown.stamp}</h3>

                  </>
                ) : (
                  <section className="bf-sec">
                    <p className="bf-p bf-quote">{morningShown.body}</p>
                  </section>
                )}

                {morningShown.isToday && (
                  <section className="bf-sec" aria-live="polite">
                    <h3 className="bf-h">Since {morningShown.stamp}</h3>
                    {since.kind === "loading" && <p className="bf-p bf-wait">Checking…</p>}
                    {since.kind === "failed" && <p className="bf-p">I couldn’t check what’s changed just now.</p>}
                    {since.kind === "lines" && since.lines.map((l, i) => <p key={i} className="bf-p">{l}</p>)}
                  </section>
                )}
              </>
            )}

            {open === "full" && (
              <div className="bf-foot">
                <button type="button" className="bf-got" onClick={() => void close()}>
                  Got it
                </button>
              </div>
            )}

            {open === "panel" && (
              <div className="bf-foot is-press">
                <p className={`bf-status${press.kind === "failed" ? " is-failed" : ""}`} aria-live="polite">
                  {press.kind === "waiting"
                    ? "Checking your sites and ShikksTracker…"
                    : press.kind === "failed"
                      ? "The Debrief didn’t finish. Try again."
                      : ""}
                </p>
                <button
                  type="button"
                  className="bf-got bf-press"
                  onClick={() => void pressDebrief()}
                  disabled={press.kind === "waiting"}
                >
                  Debrief now
                </button>
              </div>
            )}
          </div>
        </dialog>
      )}

      <dialog
        ref={cardRef}
        className="bf-card"
        aria-labelledby={cardTitleId}
        onCancel={(e) => {
          e.preventDefault();
          void closeCard();
        }}
        onClick={(e) => {
          if (e.target === e.currentTarget) void closeCard();
        }}
        onClose={() => setCard(null)}
      >
        {card !== null && (
          <div className="bf-in">
            <h3 id={cardTitleId} className="bf-h">
              {card.causeHeading}
            </h3>
            <p className="bf-p">
              <Said segments={card.cause} />
            </p>
            <h3 className="bf-h">What to do</h3>
            <p className="bf-p">{card.nextStep}</p>
            {card.raw !== null && (
              <>
                <h3 className="bf-h">Raw error</h3>
                <pre className="bf-raw">{card.raw}</pre>
              </>
            )}
            <div className="bf-foot">
              <button type="button" className="bf-got" onClick={() => void closeCard()}>
                Close
              </button>
            </div>
          </div>
        )}
      </dialog>
    </>
  );
}
