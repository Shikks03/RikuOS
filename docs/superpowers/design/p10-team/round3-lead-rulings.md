## A. The grid

**R1. `collapseRow(spans)` on the server — `ceil` first, then decrement the widest entry (ties at the last index) until the row sums to ≤ 6.** Pure, render-time, one caller. `validateLayout` is not tightened, round-down is rejected (it contradicts the deck's "rounded up" and makes span 3 identical to span 2), and `Math.max(2, ceil)` is rejected (it overflows the legal six-span-2 row). The editor does **not** import it: `+` is disabled by the twelve-column sum alone, because a `+` dimmed for a width Riku cannot see declines the move its own caption promises (C10c). The overflow condition is `Σsᵢ + #odd > 12`, which non-full rows also satisfy, so `layout.test.ts` covers `[3,3,5] → 7` as well as `[3,9]`, `[5,7]`, `[3,3,3,3]` and the untouched `[2,2,2,2,2,2]` (C10a). The trim makes equal tiles unequal at six (`[3,3,3,3] → [2,2,1,1]`); accepted, and specimen 05 draws it.

**R2. Container queries at both levels, mobile-first, on the grid's own width.** A named container `pgw` on the grid's wrapper drives the column count: the base is one column; `@container pgw (min-width:706px)` gives six columns; `(min-width:820px)` gives twelve. Thresholds are derived from the narrowest legal cell (106px at six, 125px at twelve), not from round numbers. `repeat(12, minmax(0,1fr))` and `repeat(6, minmax(0,1fr))`, never bare `1fr`; `min-width:0; overflow:hidden` on the tile. A second named container `tile` on every tile drives its own inner layout (padding, head stacking, heading size, row stacking, form columns, toolbar wrapping). No `@supports` duplication and no `@media`: a browser without container queries takes the one-column base. The design doc's 760px and 480px viewport breakpoints are struck. **Every control is measured at 1 of 6 on a 706px grid — 106px tile, 80px of inner width — before its dimensions go in the spec** (C6, critic §3.3).

**R3. Placement is three frozen class lookups per cell plus one inline track list on the grid.** The cell wrapper carries `pe-r{1..4}` (its row after compaction), `pe-s{2..12}` (its twelve-column span) and `pe-x{1..6}` (its six-column span from `collapseRow`), all emitted from `Object.freeze`d tables so an out-of-range stored value matches no rule and is *visible*. Columns are not pinned: with `grid-row` fixed and `grid-column: span N`, auto-placement packs each row left to right in DOM order and the leftover trails, which is all the editor's arrows can express. The grid's `--tracks` custom property is per-render data and is emitted inline by a pure `buildTracks(layout, editing)`: empty rows are compacted out and rows renumbered; a sparse row is `auto` (R4); each remaining row is `minmax(calc(Wpx + var(--tb)), auto)`. `--tracks` is read only inside the six- and twelve-column blocks, so the one-column stack never sees it. Every number passes through one clamping, unit-tested `buildCells`.

**R4. Row weights 340 / 180 / 240 / 120 as minimums, with the medium row held by two inner columns in Next 7 days.** Row 2 rises from the doc's 140 to 180 because the blank Layers tile measures ≈172px — a minimum content already exceeds is not a weight. Row 3 is the contested one: seven day rows at the shipped row padding measure ≈363px in one column (C2), taller than the tall row. The ruling is the Grid Architect's: **Next 7 days takes two inner columns (days 1–4 left, 5–7 right, a 14px inner gutter) at ≥ 720px of tile width**, which measures ≈235px and honours what Riku said before he specified the bento at all — *"multiple columns for the content"*. Items within a day are a wrapping flex row, so deck §13's long `Wed 21` line wraps inside its column rather than overflowing. The critic's objection — that the week's layout then changes with the tile's width — is a container-query property every tile on this page has; a two-column agenda is still chronological. **→ Riku, drawn:** the alternative is one column at every width, in which case row 3's weight rises to ≈365 and his cadence reads tall / short / tall / short; specimen 01 shows the ruled page and a B-panel with the one-column week and the taller row. Done this week stays one column and grows its row (it is the last row; growth pushes nothing). **The spec records the measured blank render beside the weights, and a build never tightens row padding below 11px, shrinks type or clips to hit a number** — if a mockup hits 240 with one column, it cheated. Re-measure after specimen 01.

**R5. A sparse row — tiles summing to fewer than 6 columns — drops its weight and takes `auto`; the rule is suspended while edit mode is open.** It shrink-wraps the empty room in the hero-moved-to-row-3 case and can never make a row taller than its weight would. The default never triggers it. Suspended in edit mode so a move never resizes a row Riku is not touching. **→ Riku:** this deviates from deck §5's *"whatever tiles sit in them"*; one sentence.

**R6. The tile: `--raised`, `1px solid var(--line)`, `--r-card` 10px, padding `15px 16px` dropping to `12px` below 200px of tile width.** The hero alone takes `--r-feature` 14px (R8). The dashed empty cell takes the radius of the tile it stands in for — `--r-card` — `1px dashed var(--line)`, no fill, no caption. Tile content is top-aligned in a stretched cell; `align-items` stays `stretch` so every tile fills its cell exactly. One exception to top alignment in R17.

**R7. The one-column step is reachable today and gets its own specimen.** The rail is a fixed 170px with no `@media`, so at a 390px viewport the content column is 164px and the stack renders (C3). "Specified but unreachable" is struck from every document. The spec says plainly: *below a 706px grid the page is a one-column stack; with the rail at 170px that is a 164px column on a phone, and the page is not usable at that width until the shell has a phone form.* **Specimen 08** draws that stack honestly at 390px beside the rail — and beside it the same viewport with the Interaction Designer's provisional shell form (a 44px top strip: brand, three nav items, `Log out`; the agents block hidden). **→ Riku, the phone shell (§K item 1).** Nothing else in P10 depends on his answer: keyed to the grid's width, the stack is correct either way.

## B. The hero and the hue budget

**R8. The hero is marked without hue, by three structural facts together: ground `#171B21`, border `--ink-4`, radius `--r-feature`.** The accent is banked — a `--session` panel over `Nothing scheduled.` is `DESIGN-INSPO` §3's Never list and §5.14 rule 2 twice over. But the reference's "current item" idiom (`#171B21` + inset hairline) was written for objects with neither fill nor border; on a bordered `--raised` tile it reduces to a 1.06:1 ground change and a hairline drawn in the colour of the border it sits inside (C1). So: keep the ground, drop the inset hairline, lift the hero's border to `var(--ink-4)` (`.btn:hover`'s shipped value, hueless, permanent), and take the radius split — `--r-card` on five, `--r-feature` on Today, because `DESIGN-INSPO` §3's table is literal and six feature radii mean no tile is the feature. All three travel with the tile when Riku moves or shrinks it (deck §14 item 3). The `--session`-eyebrow fallback is withdrawn: both its proposers agree it breaks eyebrow grammar on one tile of six. **→ Riku, visual:** specimen 01 shows the hero four ways at span 8 and again at span 4, judged against `Nothing scheduled.` / `Nothing due.`: (a) as ruled; (b) plain `--raised` with no mark; (c) `#171B21` + inset hairline only, as the team first had it; (d) the `--session` tint at a 45% stop with a `rgba(95,165,250,.2)` border — the one place his spec reserves an accent, shown so the choice is his.

**R9. Hue appears in exactly four places, all on a dot or a line of mono, and on deck §12 the page renders with zero hue.**
1. `--missing` on lateness text — `3 days late`, `1 day late` — in the due-meta column, nowhere else.
2. `--missing` on the 5px dot beside `No push this morning.`, only once the expected send time has passed (R22).
3. `--stale` on the 5px dot beside every couldn't-read sentence (R10).
4. `--stale` on the dot beside a tile-foot sentence that names a wrong state in another system — `Done, but the calendar entry couldn't be removed…`, `Saved, but the calendar entry failed…`, `…couldn't be moved…` — because that is a claim about the world, not about a press.
Nothing else: no hued count, tag, switch, tick, pill, form field, validation message, press outcome, empty cell or edit-mode surface. `--spend` stays on the focus ring and the field caret only. The decline of `DESIGN-INSPO` §5.11's layer hues is recorded as a reference-level note so Academics does not read it as binding for the Classes layer.

**R10. Every couldn't-read state is `.fl-fail`'s shape with the dot at `--stale`.** A 5px dot in a 5px track (`.fl-warn.is-stale i`'s disc and 6px glow) beside a 13px `--ink-2` sentence; the same shape on every tile at every span, because a dot beside a sentence is visible at 80px of inner width and a coloured word is not. Amber not red: a calendar that did not answer is ageing data, the reading `--stale` already carries; red stays on lateness. Kinds 1–3 in the Honesty Critic's table (measured emptiness, absence by configuration, absence of a record) take no marker. A failure sentence never truncates; it wraps and the tile grows. Every tile renders its eyebrow in every state. `.fl-bound` stays `--ink-4` — meta about the display, not a claim about the world.

## C. Tile grammar

**R11. One head grammar for six tiles: `.pe-head` = `.fl-headrow`'s two-column grid with `align-items:start`.** Left cell: `.eyebrow` (mono 9.5px / 0.18em / `--ink-3`) with, where the deck gives one, `.fl-h` beneath it (display 600, 19px, dropping to 15px below 200px of tile width — two sizes, never three) or `.fl-count` (mono 10px `--ink-3` tabular). **R12. Group labels — `SCHEDULED`, `DUE`, `PERSONAL`, `FREELANCE`, `ACADEMICS` — take `.fl-thead`'s type step at `--ink-3`: mono 500, 9px, 0.14em, uppercase.** `--ink-4` is 1.75:1 on `--raised` and is the ink this page reserves for absences; on the blank week these five labels are the page's whole structure (C4). Separation from the tile's eyebrow is carried by size, tracking and position — the eyebrow is in the head, the labels in the body under a 20px gap — and groups sit 28px apart (`.fl-group`). `.pe-grp + .fl-empty { margin-top: var(--sp-3) }`. `nothing open`, `Nothing scheduled.`, `Nothing due.` and every other measured emptiness are `.fl-empty` at 13px `--ink-3`, left-aligned where the first row would sit.

- Every name-bearing row ellipsises and never wraps; the deck's rule for event titles applies to layer names and to-do titles.

The Layers tile is `.layer` ported minus the colour dot and minus `.ct`, with the whole row as the switch.** `<button role="switch" aria-checked>` containing the name and the `.swx` pill (26×15, radius 999, `#141820`, 9px knob), `padding: 8px 0`, `--line-soft` separators, `min-height: 44px` below 480px of tile width. ## E. Honesty rulings

**R18. A day prints `—` only when every source that fills it answered; otherwise the value column is blank ground under the tile's reason sentence; with both feeds down the day rows are omitted and the row keeps its weight.** Enforced in the view-model type — `DayRowView = { key; label; items } | { key; label; unread: true }` — so `—` is unreachable for an unread day rather than merely avoided. `+N more` cannot render on an unread day. **→ Riku (content):** this deletes the seven `Fri 11 — … Thu 17 —` rows from deck §11's render (C9); one sentence to him.

**R19. On this page `—` means a day that was read and held nothing — a deliberate, recorded deviation from `DESIGN-INSPO` §5.14 rule 3.** The deck's string is Riku's and reads correctly in English; the guard is R18. Because it is a measurement it takes `--ink-3`, not `.fl-trow .dash`'s absence ink (C8). Written into the visual spec so nobody "fixes" the seven dashes into blanks or reads rule 3 as no longer binding for Academics.

**R20. Every layer switched off is a configuration state, decided before any network call.** `readCalendarWindow` returns `{ ok:false, reason:"none-enabled" }` when no layer is enabled — no token fetch, no HTTP. Today's `SCHEDULED` and the top of Next 7 days show a grey `.fl-empty` sentence naming the Layers tile, no dot, no hue (kind 2, P8 R57). `+ Event` is `disabled` with `aria-describedby` at that sentence — the same mechanism as when Google is not connected or expired (R28). The push gets its own sentence and it is **not** a counted problem. `Nothing scheduled.` is suppressed whenever any enabled layer is unread (P8 R51). Strings in §K.

**R21. Header figures are omitted under a failed read, never zeroed; failed writes reuse `Couldn't save.`; a timed-out write restores nothing.** `0 open`, Done's count and `sent 07:00` are `number | null` / `string | null` in the view model, so `0 open` above `Couldn't load to-dos.` is unrepresentable (P8 R72). Done's count is absent at zero (deck §12) while To-do's reads `0 open` — the two differ on purpose: `0 open` declares the store answered, Done's is a tally. A failed tick, un-tick, edit `Save` or layer switch reuses `Couldn't save.`; `Delete` gets `Couldn't delete.`; busy labels are `Saving…` / `Deleting…` beside the deck's `Adding…` (sentence case in the source — `.btn` uppercases as presentation, P8 R42's reading). **A failed press restores nothing locally: it clears the local hide and calls `router.refresh()`, and the server render decides whether the row comes back.** A definite failure says `Couldn't save.` under the row; a timeout — an unknown outcome — says the one new sentence in §K and never asserts the save failed (`CLAUDE.md`'s asymmetric rule). The same on a layer switch: the knob returns on a definite refusal only. Press outcomes are `.fl-note`'s recipe (11px, `--ink-3`) under a `.pe-said` class — no dot, no hue, not surviving a reload, cleared by the next press in that tile. The one exception is R9 item 4.

**R22. The push tile can tell "no push" from "no record", and its red waits for 07:00.** Three mechanisms, all adopted (C5, C15, C16):
- The *LastDigest* write sits **after** the `delivery.sent === 0` guard, is wrapped so it cannot throw, and on failure the dispatcher's `AgentRun` carries `itemsFailed: 1` — which the rail already renders as `degraded` the same morning and tomorrow's watchdog names in the push. The design doc's claim that the failure is named in *that* morning's push is struck. The write stores **`buildPushPayload`'s sliced output**, not `composeDigest`'s, so a 321-character body cannot manufacture the very state the tile reports.
- The page spends one `AgentRun` read — `fetchLatestRuns(["dispatcher"])` inside the phase-1 `Promise.all`, no round trip of its own — and the tile's states are: record for today → quote it; `run.ok && dayKey(run.startedAt, APP_TZ) === todayKey(now)` and no record → the "went out, not stored" sentence (§K) in `.fl-absent`'s register, no dot; otherwise no record → `No push this morning.` with `Last: …` beneath. The spec says what the read buys: not visibility (the rail has that) but the tile's own honesty on that one morning.
- **`No push this morning.` takes the `--missing` dot only once `now` in `APP_TZ` is past the expected send hour.** Before 07:00 the sentence stands without the dot — it is true at 00:30; only the alarm would lie. The expected hour is exported once, beside the cron's provenance, the way `AGENT_STALE_HOURS` is.

**R23. The push's Today sentence gains a partial form, and the problems fragments are lowercase.** With some layers answered and one unread, the sentence names what arrived and says which calendar was not read, and the problems line counts it, so the title never says all clear over a blind spot. `Overdue:` is omitted under a failed to-do read and the omission is covered by `Due: to-dos unavailable.`. Problem fragments are lowercase with no stop — `digest.ts` joins fragments and `end()` adds the terminal stop — so deck §10's `Calendar check unavailable.` is the rendered form, not the fragment. **→ Riku:** the partial sentence, and a nod on the casing rule (§K).

**R24. Google reads are paginated and a vanished calendar is its own state.** `listEvents` follows `nextPageToken` to a stated ceiling (three pages per layer per window); a layer still truncated at the ceiling is reported as that layer's failure (`Couldn't read Classes.`), never as a quiet day. `listCalendars` is paginated the same way. A `404` on a stored layer is `GoogleError("gone")` and gets the §K sentence naming the layer and the lever, because a 404 never clears on its own and must not share `try again later`'s register. `Connected.` on the Settings card means *a calendar list came back*: the Settings page calls `listCalendars()` once server-side and derives both cards from it, and **`GET /api/google/status` is cut** — the state between pasting the token and enabling the Calendar API is the first one Riku will hit, and only the list proves it.

**R33. Five islands, one context, no effects.** `LayoutEditor` (edit mode, the working arrangement, the header pills, the cell wrappers — always rendered, keyed by tile id, toolbar as a conditional child, `inert` toggled), `TodoRow` (one row: tick, busy, opening the edit form; one component serves four tiles), `TodoForm`, `EventForm`, `LayerSwitches`. **`LayoutEditor` also provides one page-level context holding the `Set` of hidden to-do ids**, which every `TodoRow` reads and filters itself by, so the twin of a ticked overdue to-do in the other tile leaves at the same instant (C11); the set only grows during the page's life and shrinks by one on a definite failure; the write is idempotent (`setDone(id,true)` guarded, already-done is not an error); `router.refresh()` reconciles.
