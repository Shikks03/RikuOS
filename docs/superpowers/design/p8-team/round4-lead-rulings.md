## After the quality re-review of the fix pass — 2026-09-07

The fix pass (`22b9310`, `40a8cdc`) passed its spec review and its quality re-review; the reviewer confirmed each ruling's mechanism rather than its intent (R38's timer ordering and cleanup, R39's context propagation) and withdrew both of its earlier disagreements. Three small fixes and two refinements follow, in one commit, before Task 13 calls Plan A done. Task 11 is unblocked and does not wait for them.

- **R41 — a field the singleton does not carry reads as its schema default, never as `undefined`.** `.lean()` applies no defaults, so a singleton created before a toggle existed has no such key; `readOsSettings()` would have returned `monitoringEnabled: undefined`, `isSwitchedOff` reads `!undefined` as `true`, and four badges would have asserted `off` — the exact inference from absence the rail exists to refuse. Each of the three values is defaulted with `?? OS_SETTINGS_DEFAULTS.<field>` (`??`, so a stored `false` survives), and a fourth test feeds a document carrying only `chaserEnabled`. (The reviewer's aside that `getOsSettings()` shares the exposure is not quite right — Mongoose applies defaults when it hydrates a document, and only `.lean()` skips them — but the fix is right either way.)
- **R39 addendum — the stamp's dependency on the path is a `key`, not a subscription side effect.** The bare `usePathname()` call worked because a context change re-renders its consumers, but its value reached nothing, so a memoizing compiler (`reactCompiler` is one config line away) would be entitled to cache the tree and freeze the stamp again with nothing to catch it. `useMemo(…, [pathname])` was rejected: `pathname` unused inside the callback is an `exhaustive-deps` warning, and lint must not gain one. Instead `TopBar` renders `<Stamp key={pathname} />`, a child that formats `new Date()` in its own render: the key is the same on the server and at hydration (no remount), and a navigation changes it, remounting the child and recomputing the stamp. Machine-visible, lint-clean, compiler-proof.
- **Accepted from the reviewer:** the `OsSettings` model docblock drops "always queries with the empty filter `{}` and upserts" for CLAUDE.md's wording; `deadline.test.ts` pins that the timer fires *at* the bound (4999 ms still pending, then the last millisecond); the plan's four pre-fix code blocks (Task 8 `TopBar` and `LogoutButton`, Task 9 `AgentsBlock`, Task 10 `layout.tsx`) each gain a bold "Superseded" line pointing here, because the plan's verification model is byte-exactness and a re-run would quietly regress them; Task 13 step 5 gains a line to note how long the badges take to resolve on a cold load, and to raise `RAIL_READ_TIMEOUT_MS` if that is regularly above ~2.5 s. The JSX comment inside `.crumb` stays: it documents the single-text-node decision at the line it lives on.
