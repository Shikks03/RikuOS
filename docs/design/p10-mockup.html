P10 · Personal page · Mockup

The Personal page, as ruled

Eight specimens of /personal and its shell, built to the round-3 rulings so you can judge the design in a browser before any of it is built in Next.js. Every string is taken from your content document word for word; the only invented data is the week in its §13, which exists so the full page can be drawn at all. Where a sentence is proposed it is marked in the caption and it is yours to change. No JavaScript: the switches, tick boxes and forms are drawn, not wired.

Specimen 01 · State

Your page exactly as it is today — nothing scheduled, nothing due, no to-dos yet, and one real push quoted back at you — in the default arrangement, with Personal first in the menu. There is not one coloured thing on the page: every finding here is a measured emptiness, and colour on this page is reserved for lateness and for a feed that did not answer.

Measured, not claimed. The four rows render at 340 · 198.25 · 240 · 120 pixels, so the grid is 940.25px tall. Specimen 04 · Mode

Edit layout

Four signals say this is a mode, and none of them is a colour: three pills where there was one, the whole grid sunk into a darker well, a toolbar in the foot of every tile, and the row’s leftover drawn as a dashed rectangle. The well carries a compensating negative margin, so nothing on the page moves when the mode opens. The tiles keep rendering their live data while you move them; their bodies are switched out of the tab order, so a tap is a layout gesture and never a tick.

Nothing has been changed yet, so Save and Reset to default are both disabled — the arrangement on screen already is the default. Most arrows are disabled too, and for stated reasons: ↑ in row 1, ↓ where the next row has fewer free columns than the tile is wide, + where the row already sums to 12. A move is refused before the fact, never after it.

Specimen 05 · Collapse

Twelve columns to six

A 932-pixel window leaves a 706-pixel page column, which is below the twelve-column threshold and above the six, so the grid is six wide. Every span halves, rounded up, exactly as you specified: 8 to 4, 4 to 2, 3 to 2, 12 to 6. The row weights hold. There is no leftover at six columns — row 2 is 2 + 4 = 6 and full — so the one empty cell that makes this a bento closes when the page narrows, and comes back when it widens. The collapse is done by a real container query on the grid’s own width; there is no second set of classes anywhere in the stylesheet.
